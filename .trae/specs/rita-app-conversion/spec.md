# Rita 工作台 → 可安装 APP 改造规格

## 问题

当前 Rita 生活管理工作台是一个纯前端静态网页（HTML/CSS/JS），数据仅存在浏览器 `localStorage`，存在三大局限：
1. 手机/电脑无法像原生 APP 一样安装到桌面并全屏使用（已通过 PWA 部分解决，但需公网地址手机才能安装）。
2. 数据无法在多设备间同步（换设备/清缓存即丢失）。
3. 无法以桌面安装包形式离线分发。

## 用户

Rita 本人（个人使用），在手机和电脑上记录喝水、健身、体重、穿搭妆容、英语学习、宝宝喂养与成长数据。

## 目标

1. **公网可访问**：获得一个公网 URL，手机浏览器打开即可「添加到主屏幕」安装为 PWA。
2. **桌面安装包**：生成可双击安装的桌面应用（至少 Linux 平台，提供 Windows/macOS 构建脚本）。
3. **云端数据同步**：多设备数据互通，修改后实时同步，离线时本地可用、联网后自动合并。

## 非目标

- 不做用户系统/多账号（仅单人使用，单设备标识即可）。
- 不做团队协作、权限管理。
- 不重写 UI，仅改造数据层与打包层。
- 不做复杂的冲突解决（以最后写入为准 + 时间戳）。

## 功能需求

### F1 公网部署
- 应用静态文件可通过公网 HTTPS URL 访问。
- PWA 安装提示在手机浏览器中可用。
- Service Worker 离线缓存正常工作。

### F2 桌面安装包
- 基于 Electron 打包为桌面应用。
- 桌面端全屏/独立窗口运行，无浏览器地址栏。
- 桌面端与网页端共享同一套数据同步逻辑。
- 提供 Windows (.exe)、macOS (.dmg)、Linux (AppImage) 构建产物或构建脚本。

### F3 云端数据同步
- 现有 `localStorage` 数据结构（`daily` / `baby` / `growth`）迁移至云端数据库。
- 应用启动时从云端拉取最新数据。
- 本地修改后自动/手动同步到云端。
- 离线时可正常使用，联网后自动同步未提交的更改。
- 多设备同时修改以最后写入时间戳为准。

### F4 数据兼容
- 已有的 `localStorage` 数据在首次运行时自动迁移到云端。
- 无网络或未配置云端凭据时，回退到 `localStorage` 模式，应用仍可正常使用。

## 非功能需求

- **性能**：数据同步不阻塞 UI 渲染，同步在后台进行。
- **安全**：云端访问使用服务端签发的匿名 key，不在代码中硬编码服务端密钥。
- **可维护性**：数据同步层与 UI 逻辑解耦，便于更换后端。
- **构建可复现**：构建脚本可在任意 Node 环境复现。

## 约束与依赖

- 沙箱环境为 Linux，有 Node 24 + npm 11，可访问 GitHub 与 Supabase。
- 沙箱内未登录 GitHub，无 git 仓库，无法直接推送部署。
- 沙箱内服务（如 `python http.server`）无法长期托管公网。
- 跨平台构建限制：Linux 沙箱可直接构建 Linux 包；Windows 包需 wine 或在 Windows 构建；macOS 包需 macOS 环境。

## 假设

- 用户可注册 Supabase 免费账号并提供 Project URL 与 anon key。
- 用户可提供 GitHub 账号用于 GitHub Pages 部署，或自行使用 Vercel/Netlify。
- 用户可在自有电脑上运行构建脚本生成 Windows/macOS 安装包。

## 待确认问题

- 云端后端选型：Supabase（推荐，免后端代码）还是自建 Node 后端？
- 公网部署平台：GitHub Pages、Vercel、Netlify 还是其他？
- 桌面安装包目标平台优先级：是否需要立即产出 Windows/macOS 包，还是先 Linux + 构建脚本？

## 验收标准

### AC1 公网部署
- **rule**：应用可通过公网 HTTPS URL 访问，返回 HTTP 200。
- **rule**：手机 Chrome/Edge 打开该 URL 后，浏览器提供「添加到主屏幕」或安装提示。
- **rule**：安装后以 standalone 模式全屏运行，无浏览器地址栏。

### AC2 桌面安装包
- **rule**：Electron 主进程配置正确，`npm run build:electron` 可启动桌面应用开发模式。
- **rule**：`npm run dist:linux` 可在 Linux 沙箱内产出 AppImage 或 deb 包。
- **rule**：提供 `npm run dist:win` 和 `npm run dist:mac` 脚本（在对应平台可执行）。

### AC3 云端同步
- **rule**：配置 Supabase 凭据后，数据写入同时持久化到 Supabase 数据库。
- **rule**：应用启动时从 Supabase 拉取数据并覆盖/合并本地数据。
- **rule**：离线状态下应用可正常读写本地数据。
- **rule**：恢复网络后，本地未同步的更改自动推送到云端。

### AC4 数据兼容与回退
- **rule**：首次接入云端时，现有 `localStorage` 数据自动上传。
- **rule**：未配置云端凭据时，应用使用 `localStorage` 正常工作，不报错。

### AC5 整体体验
- **rubric**：多设备同步延迟与一致性（1-5 分，阈值 3 分：同一数据在另一设备刷新后可见，延迟 < 5 秒）。
- **rubric**：安装与使用流畅度（1-5 分，阈值 3 分：安装过程 ≤ 3 步，启动后可立即使用）。
